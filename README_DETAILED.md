# 每日投研雷达 · Morning Radar

> 每天早上打开一个页面：**先看「我的持仓」有没有异动和盈亏（10 秒），再看板块轮动与技术精选，翻一眼低吸观察池和 ARTi 官方晨报，点开股票看本地 K 线 + 实时新闻 + 数据驱动的四维分析。**

一个面向**活跃个人投资者 / 量化研究者**的晨间投研终端。它不喊单、不给买卖结论。行情来自**本地 MySQL 库（wucai_trade）**（500 万+ 日线、130 个申万板块）；板块真资金可切**同花顺实时**（东财 f62 主力净流入兜底）；新闻来自**实时公开接口**（东财快讯 + 财联社电报，每 15 分钟刷新）；分析基于**真实数据**生成，每条结论都能追溯到具体指标或新闻标题。

页面共 4 个主视图：**全市场雷达 / 我的持仓 / ARTi 晨报 / 低吸观察池**。

## 一页说明

### 解决谁的什么问题

| | |
|---|---|
| **给谁** | 每天想快速把握板块机会、但没时间逐个翻行情和研报的个人投资者 |
| **痛点** | ① 早上信息过载，不知道钱往哪个板块流；② 看 K 线要开多个软件、手动加指标；③ 想看消息面和不同视角的观点，得翻一堆地方；④ 超跌股看着便宜，但不知道有没有资金真进场 |
| **怎么解决** | 一个页面串起来：**持仓异动与盈亏 → 板块轮动热力图 → 每板块 3-5 只技术精选 → 点击看 K 线（5 种指标切换）→ 实时新闻 + 数据驱动的新闻分析 / 投研报告 / 大师总结 / ARTi 智能解读**；另有**低吸观察池**（超跌 + 缩量企稳 + 板块真资金流入）与 **ARTi 官方早晚报** |
| **为什么这样设计** | ① **信息分层**：先看自己的持仓，再看板块（宏观到微观），再看个股，符合真实投研动线；② **可解释选股**：每只股票附带触发的技术信号和五维评分，不是黑箱；③ **真实数据驱动**：新闻实时抓取、分析引用具体指标/标题，不输出空泛模板套话；④ **资金否决权**：低吸候选必须叠加「所属板块真资金净流入 > 0」，宁缺毋滥；⑤ **不越界**：只给技术信号和多方观点，明确「不构成投资建议」，决策权留给用户 |

### 核心功能

0. **我的持仓简报（方向一 · 个性化）**
   - 用户输入自选股，每天只推"和我有关的变化"：**大涨大跌 / 放量 / 均线突破跌破 / MACD 金叉死叉 / 新闻命中 / 盈亏触及参考线**
   - 三段式 10 秒看懂：① 概览数字（需关注 N / 自选 N）② 一句话摘要 chips ③ 异动卡片（每条含为什么值得看）
   - **成本价与盈亏**：自选股可填成本价，卡片按 `(现价/成本-1)` 显示持仓盈亏（浮盈红 / 浮亏绿，A 股习惯）；从低吸池加入时自动填入当时的显示价格
   - **ARTi 持仓去留诊断**：把股票名称 + 当前情况（现价/涨跌/评分/基本面/消息面）+ 本次触发的每一条异动喂给 ARTi，输出「持有 / 减仓 / 平仓」结论 + 理由 + 关键价位 + 风险；无 Key 时本地规则引擎兜底并明确标注
   - **不打扰设计**：无实质异动时明确显示"今天无需关注"；午间休市为静默时段，只记录不推送
   - 自选股与阈值可在界面上直接管理（`/api/watchlist`），存 `watchlist.json`

1. **板块轮动**
   - Treemap 热力图：颜色=涨跌幅（红涨绿跌），面积=成交额；支持列表视图，一眼看资金流向
   - 轮动评分 = 涨幅排名 50% + 资金净流入排名 50%，按综合分取 TOP3 板块
   - 数据源可切：`SECTOR_SOURCE=mysql` 走本地库 130 个申万二级板块；`SECTOR_SOURCE=ths` 走**同花顺实时细分板块**（带东财 f62 主力净流入兜底），盘中缓存 1 分钟、非交易时段 2 小时

2. **技术面选股**（每板块 3-5 只）
   - 五维加权评分：趋势(30) + 动量(25) + 量能(20) + 位置(15) + 超跌反弹(10)
   - 每只股票输出可解释信号：均线多头排列 / MACD 金叉 / RSI 强势区 / 放量 / KDJ 低位金叉…
   - 并发扫描成分股，秒级出结果；K 线先清洗 `volume=0` 占位行与僵尸股，避免把停牌/未更新数据算成"缩量"

3. **K 线 + 技术指标**
   - 前复权日 K，红涨绿跌（A 股习惯）
   - 5 种指标一键切换：MA 均线 / MACD / BOLL / RSI / KDJ
   - 成交量联动、十字光标、数据溯源标注；抽屉重复打开会正确销毁并重建图表实例

4. **实时新闻 + 数据驱动四维分析**（按需 + 缓存）
   - 📰 抽屉内展示**实时新闻**：东财 724 快讯（600 条/3 页，自带股票代码关联）+ 财联社电报（40 条），15 分钟刷新；本地资讯库仅作历史补充，界面明确区分
   - 📰 **新闻分析**：合并实时快讯 + 资讯库新闻统一梳理；**从标题自动提取关键数据**（如"净利2.9亿·同比降8.5%""投资4.22亿→1.85亿""拟募资35亿扩产"）；自己判情绪分积极信号/风险点/其他动态；无数字时诚实展示标题，不编造
   - 📋 **投研报告**：引用真实指标数值（MA5/20/60、MACD DIF/DEA、RSI、布林上下轨、量比、近 20 日涨跌）生成研判
   - 🎓 **大师总结**：三方圆桌各自引用真实数据发言——价值派看财报（营收/净利同比、毛利率、ROE、机构EPS预期/PE/目标价）、趋势派看 K线指标、风控官盯经营现金流与负债率，并给出当期财报日期和研报来源，可追溯
   - 🤖 **ARTi 智能解读**：与上面三个 tab 同一行切换，是**纯 ARTi 联网独立研报**（`kind=arti`），不套本地模板
   - 情绪标签为关键词规则判定；正文提及但非本股主体的新闻自动降级为中性，避免误导
   - **速度设计**：本地数据引擎**秒回**，ARTi 增强走后台线程池异步（2 并发、3 次重试、2/4 秒退避），前端轮询补齐；失败显示原因与重试按钮，不阻塞页面
   - **徽标是诚实标注**：配了 Key 时，非 ARTi tab 显示「本地数据 + ARTi」（先本地秒回，再异步叠加），ARTi tab 显示「ARTi 联网研报」；未配 Key 时分别降级为「本地数据引擎」/「ARTi 未接入 · 本地」，不假装是联网结果。不配 Key 也能输出完整分析
   - 缓存：本地引擎 10 分钟（跟随行情），ARTi 结果 7 天；打开抽屉默认加载新闻分析，无需手动点 tab

5. **低吸观察池（反转低吸 · 观察工具，非买入信号）** 🆕
   - 定位：把「低关注 + 缩量企稳 + 超跌」的候选股摆出来供人工复核，**不是买入信号**
   - **A 组 超跌型** / **B 组 缩量企稳型** 双分组切换，按 `ret3↑ / volr↓ / 换手↓` 分位 + 近20日跌幅分位排序
   - 硬门槛（全部满足才入池）：
     | 条件 | 阈值 |
     |---|---|
     | 缩量：近3日均量 / 前20日均量 | ≤ 0.85 |
     | 近3日转涨 | > 0 |
     | 低关注：当日换手率 | ≤ 3% |
     | A组超跌：近20日跌幅 | ≤ -8% |
     | **所属板块真资金净流入** | **> 0** |
   - **资金硬条件怎么算**：同花顺实时 f62 主力净流入 → 按「申万一级行业 → 同花顺细分板块」映射聚合（如家用电器 → 白色家电/黑色家电/小家电/厨卫电器）；资金合计 ≤ 0 的行业，其候选股一律剔除。当前多数板块资金流出，所以候选很少属正常现象
   - 页面上方**单列「真资金流入板块」卡片**（板块名 + 净流入亿元 + 涨跌幅），表格每行标注个股所属申万一级及**具体贡献资金的细分板块**（如 `家用电器 / 白色家电 +5.69亿`），知道钱到底进的是哪一块
   - **点击表格任意一行 → 打开股票详情抽屉**（K 线 / 实时新闻 / 四维分析），与全市场雷达中的股票点击行为完全一致
   - **「加入持仓」按钮**：一键把该股加入自选，成本价自动取**当时表格显示的价格**，代码规范化为 6 位并按代码去重；随后「我的持仓」卡片即显示该股盈亏
   - 数据：本地 MySQL `trade_stock_daily`（近 120 日）+ `trade_stock_status`（申万行业映射）；每只股票用自己的**最新有效成交日**（`volume>0`）算信号，规避当日零量占位行；结果缓存 30 分钟（`dip_cache.db`）
   - **回测结论（务必看）**：超跌缩量企稳 TOP10 在 2024-07 ~ 2026-10 共 110 期相对全市场等权基准，10 日超额 +1.19%、胜率 54%，但多空分组反向、2025-08 后失效 → 故本页只作观察，并叠加资金硬条件做二次过滤

6. **ARTi 官方晨报 / 晚报** 🆕
   - 直读 ARTi 官方公开内容接口（Supabase REST `content_briefs.body_html`），无需浏览器渲染，页面内完整呈现当日早报/晚报
   - 早报 / 晚报一键切换、可指定日期、强制刷新；缓存 1 小时（`arti_brief.db`），失败时回退最近一期同类晨报，保证页面始终有内容
   - 页脚给出原文链接，来源标注清楚

7. **本地财务数据接口**（为"买前三问"等方向预留）
   - `/api/financial/{code}` 返回营收/净利/ROE/毛利率/负债率/现金流等季度数据

## 快速开始

```bash
cd market-radar
pip install -r requirements.txt

# 方式 A：用你自己的 ARTi Key（本地数据引擎 + ARTi 增强解读，可选）
# Linux/macOS:
# cp .env.example .env
# Windows PowerShell:
# Copy-Item .env.example .env
# 编辑 .env，填入 ARTI_API_KEY=sk-arti-你的key
# 如需同花顺实时板块真资金：加一行 SECTOR_SOURCE=ths

# 方式 B：无 Key 也能跑（本地数据引擎生成全部分析，新闻实时抓取，其余全真实数据）
# 什么都不用配

# 启动
python -m uvicorn web.app:app --host 127.0.0.1 --port 8766
# 浏览器打开 http://127.0.0.1:8766
```

> **本地 MySQL 优先**：设置 `WUCAI_SQL_PASSWORD` 环境变量后，行情全部走本地库（行情本身无需外网）。板块真资金建议 `SECTOR_SOURCE=ths`（同花顺实时，东财 f62 兜底）；新闻走实时公开接口（东财/财联社，需外网）。未设置 MySQL 密码或连接失败时行情自动降级到 akshare → 内置数据，界面明确标注数据源。

> **ARTi 官方晨报**无需 Key（读的是官方公开内容表），但需外网；**智能解读 / 持仓去留诊断**在配置了 `ARTI_API_KEY` 后才走真实 ARTi，否则由本地规则引擎兜底。

### 环境变量（可选）

| 变量 | 默认 | 说明 |
|---|---|---|
| `WUCAI_SQL_PASSWORD` | 空 | **本地 MySQL（wucai_trade）密码**，设置后启用本地行情主数据源 |
| `WUCAI_SQL_HOST` / `WUCAI_SQL_PORT` / `WUCAI_SQL_USER` / `WUCAI_SQL_DATABASE` | 127.0.0.1 / 3306 / root / wucai_trade | MySQL 连接参数 |
| `SECTOR_SOURCE` | `mysql` | `mysql`=本地库申万二级板块；`ths`=**同花顺实时细分板块**（带真资金 f62，低吸池资金硬条件依赖它） |
| `SECTOR_CACHE_MINUTES` | 自动 | 板块缓存分钟数；不填则交易时段 1 分钟、非交易时段 2 小时 |
| `ARTI_API_KEY` | 空 | ARTi 开发者 Key，不填则只用本地数据引擎（功能完整）；填了则叠加 ARTi 增强解读与持仓诊断 |
| `ARTI_MOCK` | `0` | 设为 `1` 强制关闭 ARTi 增强（省 credits），不影响本地数据引擎 |
| `TOP_SECTORS` | `6` | 首屏扫描的板块数（轮动评分 = 涨幅排名50% + 资金净流入排名50%） |
| `STOCKS_PER_SECTOR` | 4 | 每板块精选股票数 |

> **密码安全**：密码只读环境变量，绝不写入代码或仓库。Windows PowerShell 临时设置：`$env:WUCAI_SQL_PASSWORD="你的密码"`。

                                              ──→ 新闻分析/投研报告/大师总结（每个角色引用不同数据源）

### 关键工程决策

- **本地优先**：MySQL 可用时行情全部本地化，零外网依赖、零代理超时；不可用时才走网络降级链
- **降级链 + 全局开关**：MySQL 连续失败暂停 5 分钟重试；网络探测失败则关闭网络尝试，避免重复超时；板块日期取板块表自身最新日期，不与个股日期错配
- **真资金而非涨跌幅**：板块/低吸池用主力净流入（同花顺实时、东财 f62 兜底）做硬条件，超跌股没有资金认可就宁可空着
- **K 线清洗**：`_clean_kline()` 剔除 `volume=0` 占位行、连续同价僵尸股，否则异动检测的涨跌幅/量比会恒为 0（曾导致持仓页"全部无异常"）
- **代码格式适配**：内部统一 6 位代码，MySQL 用 `600519.SH` 格式，转换封装在 mysql_source；快讯用 `1.600519`/`0.002594` 前缀，转换封装在 live_news；加入持仓时 `002011.SZ → 002011` 规范化并去重
- **界面明确标注 `source`**：本地MySQL / 实时抓取 / 历史补充 / 模拟数据一眼可辨；智能分析徽标按当前 tab 与 Key 状态显示「本地数据 + ARTi」/「ARTi 联网研报」或「本地数据引擎」/「ARTi 未接入 · 本地」，不假装是实时联网结果
- **新闻实时化 + 情绪纠偏**：本地新闻表滞后时自动用实时快讯补充；正文提及但非本股主体的新闻情绪降级为中性，避免把别人的利空套到本股
- **慢调用不阻塞**：ARTi 单次 15~30 秒且偶发 502，改为本地秒回 + 后台异步增强 + 轮询 + 失败原因/重试按钮；并发压到 2 提升成功率
- **并发扫描**：板块、成分股、K线全部线程池并发
- **缓存分层**：行情 SQLite（6-12h）、板块（盘中1min/盘后2h）、新闻 SQLite（15min）、分析 SQLite（本地10min/ARTi 7天）、低吸池（30min）、晨报（1h）
- **数据驱动分析**：每条结论引用具体指标数值或新闻标题；无实时新闻时诚实告知而非编造；不配 ARTi key 也能输出完整分析
- **按需加载**：低吸池、ARTi 晨报、抽屉里的分析 tab 都是切到才加载，首屏不拖慢
